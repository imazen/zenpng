# PNG scan predicates on macOS ARM64, 2026-10-16

Source `9463c62b`, M4 Pro. Command: `~/work/claudehints/scripts/run-heavy --mem 12G --jobs 4 -- just arm-scan-tiers-macos`. The recipe ran `cargo bench -p zenpng --bench scalar_vs_simd --features _dev -- --cpu-policy=unrestricted --format=llm`. Full output: `~/tmp/png-arm-scan-tiers.log` on this Mac. The scheduler was unrestricted, so treat the results as exploratory.

At 1024 × 1024 pixels, the full-scan means were:

| Predicate | Scalar | Runtime SIMD |
| --- | ---: | ---: |
| Opaque RGBA8 | 342.63 µs | 36.40 µs |
| Grayscale RGBA8 | 286.16 µs | 52.92 µs |
| Binary alpha RGBA8 | 364.74 µs | 43.33 µs |
| Grayscale RGB8 | 336.18 µs | 41.90 µs |
| Lossless BE16 bit replication | 1.02 ms | 106.27 µs |

The fused three-check scan was 1.38 ms scalar, 96.72 µs runtime SIMD, and 84.11 µs with the const-generic SIMD entry. Production format optimization already calls the const-generic entry (`src/optimize.rs`), so that measured difference does not suggest a route change. The benchmark also checks result equality before timing each size.

`run-heavy`: peak RSS 0.99 GiB, minimum available memory 5231 MiB, peak load 1.88.
